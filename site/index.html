    Where the time goes

    Score traffic in the naive kernel grows with the square of sequence length; flash attention's grows linearly. The roofline places each kernel against the Tensor Engine's BF16 peak and the core's share of HBM bandwidth.

    Matmul and normalization kernels

    Blocking keeps a 2×4 or 4×2 grid of accumulators in the 8 PSUM banks so every loaded tile is reused. Fused softmax and RMSNorm read each row from HBM once.

    How the numbers are made

    Measured Correctness, instruction counts per engine, DMA bytes, FLOPs and per-partition SBUF/PSUM footprint. These come from the instructions the kernels actually issue on the NKI CPU simulator.

    Modeled Every latency on this page. The simulator reports no timing, so a first-order model of one Trainium2 NeuronCore-v3 assigns each instruction a cost and list-schedules it onto in-order engine queues, honouring buffer dependencies. Treat latencies as a way to compare variants, not as hardware measurements.

    From AWS's Trainium2 architecture guide: Tensor Engine 79 TFLOPS BF16 and 20 TFLOPS FP32 at 2.4 GHz; Vector Engine 0.96 GHz with 512 (16-bit) or 256 elements per cycle; Scalar Engine 1.2 GHz, 128 elements per cycle; SBUF 224 KiB and PSUM 16 KiB per partition; 3 TB/s HBM per 8-core chip; 16 DMA engines per core; about 600 ns per hardware-DGE DMA.

    Assumptions, not documented: HBM bandwidth splits evenly across cores (375 GB/s each); NeuronCore-v2 fixed instruction overheads (64 Tensor, 100 Vector, 64 Scalar cycles) carry over to v3; GpSimd runs at Scalar Engine width; buffers are unlimited, so DMA prefetch overlaps as far as dependencies allow.
